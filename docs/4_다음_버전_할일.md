# 다음 버전에 할 일 (v1 이후)

> 2026-09-19. 이 앱의 자동토론 기능으로 세 모델(클로드 Opus · ChatGPT gpt-5.6-sol · 헤르메스)에게
> "공개판 v1에서 다음에 뭘 고칠까"를 3라운드 토론시킨 결과를 정리한 문서입니다.
> 토론 원문은 배포자의 관제판 보드에 남아 있습니다.

## 이미 반영한 것 (v1.1)

- **계정 사전 확인.** 회사·학교(Workspace) 계정은 관리자가 Apps Script를 막아뒀을 수 있다. 그 경우 정확히 따라 해도 실패하는데, 문서에 그 말이 없으면 사용자가 자기 손을 의심하며 시간을 태운다. 설치 문서 맨 앞에 1분짜리 확인 방법을 넣었다.
- **권한 경고 화면 안내.** `/copy` 직후 첫 실행에서 뜨는 "Google에서 확인하지 않은 앱입니다" 경고는 비개발자가 되돌아가는 최대 지점이다. 왜 뜨는지와 `고급 → (안전하지 않음)으로 이동` 까지 단계로 적었다.
- **경로 선택표.** 작업보드만 쓸 사람과 자동토론까지 갈 사람을 README 앞에서 갈랐다. 필요 없는 사람을 CLI 설치로 보내지 않기 위해서다.
- **호출 상한과 예상치 표시.** 자동토론 시작 화면에 `예상 AI 호출: 3명 x 3라운드 = 최대 9회 (상한 30회)` 를 찍고, `토론.최대호출` 에 닿으면 도중에 멈춘다. 실행 확인 버튼은 잘못 눌리면 그대로 호출이 나가지만, 상한은 잘못 눌러도 막아준다.
- **기본값 중립화.** 설치 직후 보이는 예시 프로젝트·행위자 이름을 만든 사람의 실제 업무 이름에서 중립적인 것으로 바꿨다.
- **드라이버 구조 변경.** 게시판을 읽고 쓰는 일을 전부 드라이버가 맡고, AI는 발언만 파일로 넘긴다. 한글 인코딩이 한 곳에서만 처리되고, 앱 주소·토큰이 AI에게 넘어가지 않는다.

## 아직 안 한 것 (후보)

- **첫 실행 안내.** `seedExampleData` 로 예시 데이터를 넣는 기능은 이미 있지만 설치 문서에 "(선택)"으로 묻혀 있다. 앞으로 꺼내고, 기존 데이터를 지우지 않는 추가 전용이라는 점을 명시할 것. (토론 참가자 셋 다 "예시 업무 온보딩을 만들자"고 했으나, 실은 절반이 이미 있다.)
- **설치 스모크 테스트.** 설정 파싱·시트 연결·CLI 존재 여부처럼 기계로 판정되는 구간만 스크립트로 묶는다. 권한 동의 화면은 자동화할 수 없으므로(자동화하려면 이미 승인된 계정을 써야 하고, 그러면 정작 사람이 되돌아가는 화면만 건너뛴 테스트가 된다) 사람이 한 번 찍어 고정한 문서로 분리한다.
- **참가자 사전검증.** 지금은 CLI가 PATH에 있으면 참가자로 잡는다. 설치는 됐지만 로그인이 안 된 흔한 상태를 못 거르므로, 라운드 중간에 죽고 토론이 반쯤 끊긴다. 실패한 참가자는 제외하고 남은 인원으로 계속 가되 이유를 한 줄로 알릴 것.
- **실행 기록.** 참가자·모델·라운드·종료 사유 네 필드면 충분하다. v1에서 스키마를 크게 잡으면 나중에 고칠 때 이미 쌓인 기록과 호환을 맞추느라 더 비싸진다.

## 넣지 않기로 한 것

세 모델이 이유까지 똑같이 말한 항목들이다.

- **로그인 대행 서버 · OAuth 프록시 · 공용 서버.** 넣는 순간 키 보관·가동률·남용 대응 책임이 생기고, 나눠주는 템플릿이 운영해야 하는 서비스로 바뀐다.
- **원격 텔레메트리 / 실행 이력 중앙 수집.** 공개 템플릿에서 계정·비용 관련 기록을 모으기 시작하면 동의·보관·삭제 경로가 새로운 설치 장벽이 된다.
- **알림 · 다중 사용자 권한 관리 · 대시보드 꾸미기.** 유지보수가 늘고, 첫 설치 성공률을 올리는 일보다 우선할 근거가 없다.

## 결론이 안 난 쟁점

- **검증을 사람으로 할까 기계로 할까.** 새 계정 몇 명에게 직접 시켜보자는 쪽과, 재현 가능한 무인 테스트를 먼저 만들자는 쪽이 갈렸다. 권한 동의 화면은 기계가 못 넘는다는 반박이 나온 뒤로 "기계 판정 구간만 자동화, 나머지는 수동"으로 기울었지만 확정은 아니다.
- **비용 안전장치의 형태.** 라운드 상한 → 총 호출 수 상한 → 실행별 예산 회계 순으로 제안이 무거워졌다. v1.1에는 총 호출 수 상한만 넣었다.
- **혼자 돌릴 때.** CLI 하나만 있는 사람을 위해 한 CLI가 두 역할을 번갈아 맡게 할지, 아니면 1인 토론을 정상 모드로 인정할지 갈렸다. 역할을 번갈아 맡기면 비용·모델 편향이 참가자 수처럼 보이는 기록이 남는다는 지적이 있었다.
