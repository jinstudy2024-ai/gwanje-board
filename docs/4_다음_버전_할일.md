# 다음 버전에 할 일 (v1 이후)

> 2026-09-19. 이 앱의 자동토론 기능으로 세 모델(클로드 Opus · ChatGPT gpt-5.6-sol · 헤르메스)에게
> "공개판 v1에서 다음에 뭘 고칠까"를 3라운드 토론시킨 결과를 정리한 문서입니다.
> 토론 원문은 배포자의 관제판 보드에 남아 있습니다.

## 이미 반영한 것 (v1.1)

- **계정 사전 확인.** 회사·학교(Workspace) 계정은 관리자가 Apps Script를 막아뒀을 수 있다. 그 경우 정확히 따라 해도 실패하는데, 문서에 그 말이 없으면 사용자가 자기 손을 의심하며 시간을 태운다. 설치 문서 맨 앞에 1분짜리 확인 방법을 넣었다.
- **권한 경고 화면 안내.** `/copy` 직후 첫 실행에서 뜨는 "Google에서 확인하지 않은 앱입니다" 경고는 비개발자가 되돌아가는 최대 지점이다. 왜 뜨는지와 `고급 → (안전하지 않음)으로 이동` 까지 단계로 적었다.
- **경로 선택표.** 작업보드만 쓸 사람과 자동토론까지 갈 사람을 README 앞에서 갈랐다. 필요 없는 사람을 CLI 설치로 보내지 않기 위해서다.
- **호출 상한과 예상치 표시.** 자동토론 시작 화면에 `예상 AI 호출: 3명 x 3라운드 = 최대 9회 (상한 30회)` 를 찍고, `토론.최대호출` 에 닿으면 도중에 멈춘다. 실행 확인 버튼은 잘못 눌리면 그대로 호출이 나가지만, 상한은 잘못 눌러도 막아준다. (상한을 2회로 낮춰 실제로 세 번째 참가자 차례에서 멈추는 것까지 확인했다.)
- **기본값 중립화.** 설치 직후 보이는 예시 프로젝트·행위자 이름을 만든 사람의 실제 업무 이름에서 중립적인 것으로 바꿨다.
- **첫 실행 안내.** 설치 직후 화면은 비어 있고, 처음 받는 사람은 그 빈 화면을 고장으로 읽는다. `seedExampleData` 는 원래 있던 기능인데 설치 문서 3단계 안에 "(선택)" 한 줄로 묻혀 있어 눈에 띄지 않았다. 별도 6단계로 꺼내고, 무엇이 들어오는지(잠금 3·카드 4·지시문 1·일지 5줄)와 치우는 법까지 적었다. 이 기능은 **추가 전용이 아니라 빈 시트 전용**이다 — 잠금·보드·지시문 중 하나라도 내용이 있으면 실행해도 거부하고 아무것도 바꾸지 않는다. 문서에는 정정한 쪽으로 적었다. (토론 참가자 셋 다 "예시 업무 온보딩을 만들자"고 했으나, 실은 절반이 이미 있었다.)
- **참가자 사전검증.** 토론 시작 전에 참가자를 한 명씩 짧게 불러 실제로 대답하는지 본다(파일에 `READY` 한 단어 쓰기). 대답 못 하면 이유를 한 줄로 알리고 빼며, 남은 인원으로 그대로 진행한다. 토론 중에도 연속 2회 응답이 없으면 같은 방식으로 뺀다. 검증도 진짜 호출이라 `최대호출` 상한에 포함시키고, 설정으로 끌 수 있게 했다 — 공짜로 안전해지는 게 아니라 참가자 수만큼 호출을 먼저 쓰는 거래다.
  첫 구현은 시간 제한을 걸려고 검증만 백그라운드 작업으로 불렀는데, npm 셸 래퍼로 설치된 CLI(claude·codex)가 그 환경에서 시작하자마자 죽어 **멀쩡한 참가자 둘을 "로그인 안 됨"으로 잘못 걸러냈다.** 검증 경로를 본 경로와 똑같이 되돌려 고쳤다. 교훈: 확인용 코드를 본 코드와 다른 방식으로 부르면, 확인하는 건 대상이 아니라 그 방식이다.
- **사본 버전 표시와 업데이트 안내.** 앱 코드에 `APP_VERSION` 을 두고 화면 오른쪽 위에 찍는다. `action=version` 으로도 읽힌다. `CHANGELOG.md` 를 만들어 맨 위 번호와 비교하면 최신인지 알 수 있게 했고, 두 값이 어긋나면 테스트가 실패한다.
  만들면서 화면에 버전이 끝내 안 찍히는 일이 있었다. 서버는 값을 보냈고 그리는 줄도 있었는데 **그 사이에서 값을 옮기는 한 줄**이 빠져 있었다. 화면(HTML)은 구글 서버에서만 돌아 테스트 밖이라 아무도 못 잡았다. 그래서 13번 테스트를 새로 만들어 화면 스크립트의 문법과 `status` 응답 값들의 배선을 검사하게 했고, 배선을 일부러 빼서 실제로 실패하는 것까지 확인했다.
  걱정했던 데이터 이관 문제는 **없었다.** "새 사본을 만들라"가 아니라 **쓰던 시트에 코드만 갈아끼우는 것**이 맞는 안내였고, 그러면 데이터도 토큰도 주소도 그대로 남는다. 다만 `배포 관리 → 편집 → 새 버전` 이 아니라 `새 배포` 를 누르면 주소가 바뀌어 옛 주소가 옛 코드를 계속 보여주므로, 그 함정을 문서에 경고로 박았다.
- **드라이버 구조 변경.** 게시판을 읽고 쓰는 일을 전부 드라이버가 맡고, AI는 발언만 파일로 넘긴다. 한글 인코딩이 한 곳에서만 처리되고, 앱 주소·토큰이 AI에게 넘어가지 않는다.

## 아직 안 한 것 (후보)

- **권한 없이 써보는 빠른 시작.** 지금은 아무것도 해보기 전에 Apps Script 권한 승인부터 거쳐야 한다. 회사 계정이라 막힌 사람은 물론이고, 보안 경고에서 되돌아가는 사람도 이 도구가 뭘 해주는지 끝내 못 본다. 템플릿 기본 상태에서 **권한 호출 없이** 시트 안의 예시 업무를 직접 고쳐 완료까지 가보는 경로를 만들면, 막힌 계정도 쓸모를 먼저 느낀 뒤 설치를 결심할 수 있다.
- **설치 스모크 테스트.** 설정 파싱·시트 연결·CLI 존재 여부처럼 기계로 판정되는 구간만 스크립트로 묶는다. 권한 동의 화면은 자동화할 수 없으므로(자동화하려면 이미 승인된 계정을 써야 하고, 그러면 정작 사람이 되돌아가는 화면만 건너뛴 테스트가 된다) 사람이 한 번 찍어 고정한 문서로 분리한다.
- **실행 기록.** 참가자·모델·라운드·종료 사유 네 필드면 충분하다. v1에서 스키마를 크게 잡으면 나중에 고칠 때 이미 쌓인 기록과 호환을 맞추느라 더 비싸진다.

## 넣지 않기로 한 것

세 모델이 이유까지 똑같이 말한 항목들이다.

- **로그인 대행 서버 · OAuth 프록시 · 공용 서버.** 넣는 순간 키 보관·가동률·남용 대응 책임이 생기고, 나눠주는 템플릿이 운영해야 하는 서비스로 바뀐다.
- **원격 텔레메트리 / 실행 이력 중앙 수집.** 공개 템플릿에서 계정·비용 관련 기록을 모으기 시작하면 동의·보관·삭제 경로가 새로운 설치 장벽이 된다.
- **알림 · 다중 사용자 권한 관리 · 대시보드 꾸미기.** 유지보수가 늘고, 첫 설치 성공률을 올리는 일보다 우선할 근거가 없다.

## 결론이 안 난 쟁점

- **검증을 사람으로 할까 기계로 할까.** 새 계정 몇 명에게 직접 시켜보자는 쪽과, 재현 가능한 무인 테스트를 먼저 만들자는 쪽이 갈렸다. 권한 동의 화면은 기계가 못 넘는다는 반박이 나온 뒤로 "기계 판정 구간만 자동화, 나머지는 수동"으로 기울었지만 확정은 아니다.
- **비용 안전장치의 형태.** 라운드 상한 → 총 호출 수 상한 → 실행별 예산 회계 순으로 제안이 무거워졌다. v1.1에는 총 호출 수 상한만 넣었다.
  마지막 라운드에서 "예산 원장은 파일 잠금과 강제 종료 복구가 이 프로젝트에서 가장 만들기 어려운 코드인데, 정작 그 고장 화면은 받는 사람이 읽어낼 수 없는 문장이라 상한 하나로 막히는 문제에 새 막힘을 얹는 꼴"이라는 반론이 나왔고, 설정 매니페스트도 같은 이유로 v1에서는 빼는 쪽으로 기울었다. 지금 상태(상한 하나 + 예상 호출 표시)가 그 결론과 맞다.
- **혼자 돌릴 때.** CLI 하나만 있는 사람을 위해 한 CLI가 두 역할을 번갈아 맡게 할지, 아니면 1인 토론을 정상 모드로 인정할지 갈렸다. 역할을 번갈아 맡기면 비용·모델 편향이 참가자 수처럼 보이는 기록이 남는다는 지적이 있었다.
